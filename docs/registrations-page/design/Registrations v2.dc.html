10Registrations × refresh jobs — one matrix · plus the first-run empty state · dark and light, desktop and mobile
A grant and its refresh job are the same cell. The pattern is a CI matrix (GitHub Actions, Datadog synthetics): rows are the thing being polled, columns are the job type, and each cell is the last run. Here a cell shows the grant icon and the last refresh time — so "never" next to a red ✕ answers its own question: the job never runs because there is no grant. No separate jobs page to cross-reference.
Bulk triggers live on the axes. The ↻ in a column header refreshes that scope across every character that has it; the ↻ at the end of a row refreshes everything for that character; a single cell refreshes on its own ↻ (shown on the active cell). Cells without a grant have no trigger — nothing to run.
The empty state is the matrix, ghosted. A first-run user shouldn't land on a marketing panel — they land on the actual instrument, drawn faint, with one dashed row where their first character will appear. The columns are already labeled, so the CTA doesn't have to explain what registering unlocks — the empty grid does. One primary action, no plea.
10aDesktop — the matrix. Template row zero, grant icon + last-refresh per cell, ↻ per column (all characters), ↻ per row (all jobs for a character). Kel's wallet cell shows the payoff: "never — no grant".
