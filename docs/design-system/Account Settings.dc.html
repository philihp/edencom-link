12Buttons & links — lavender means clickable, gray means readout · dark and light
One hue means clickable. Links already own the lavender — buttons now borrow it: same color, same 600 weight. An outline in that color is a button; bare, it's a link. Nothing inert gets to wear it.
Primary is the same rule, filled. The one action a screen exists for gets the solid fill; everything else is outline or bare. Never two solids in one view. Destructive commits swap the lavender for status-bad, in both button and link form.
Gray is demoted to readout. The gray-bordered ghost button is retired from actions: a gray border now marks an inert field or a reading — a token, a rate, a select's body (its lavender chevron is the clickable part). Already applied to 11a below: log off, regenerate, generate new code.

11Account settings as a control panel — grouped by data direction, every panel labeled by how it changes · dark and light
Every panel is tagged by how it changes. [ credential ] is how you get back in; [ declared ] changes only when you edit it; [ live ] moves on its own. The tag answers the question a settings page never answers: is this value stale because I forgot it, or fresh because the system maintains it? A legend under the title teaches the vocabulary once.
Grouped by direction of data, not by feature. Today's page is ten h2s in the order they were built. Here: identity (who you are), declared inputs (what you've told us — grants template, tax rates), live connections (what flows out — Discord, Sheets), administration. A new panel has an obvious home.
Readouts first, forms second. Every panel shows its current value as an instrument reading (mono, glanceable) — the tax panel shows 0.100% / 1.000% without a form in sight; editing is an action you take, not two number inputs permanently staring at you. The current page renders every form expanded forever.
11aDesktop — four groups, eight panels. Group rules carry an annotation ("changes only when you edit" vs "moves on its own"); live panels get a health dot in the header. Log off is a header action, not a section.
